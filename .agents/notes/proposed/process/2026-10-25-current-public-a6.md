# Decision: select verified public a6 in current SDK guidance

Status: proposed

## Problem

Current guides, two Skills and offline fixture recipes still select a4 after
immutable a6 publication and independent official artifact/installation checks.
The delivered help/API corrections need accurate current installation guidance.

## Decision

Select exact public a6 with the existing official index in maintained installs
and both fixture recipes; align the existing guest-version assertion. Accept the
already merged/published Template and Sandbox help notes using actual facts.
Add new dated public-a6 delivery and 14-cloud/local example evidence; preserve all historical receipts, initial
metadata404 observations and prior browser failures. No API or example execution
code changes; the decorator example changes only its installation docstring.

## API Design

N/A — no SDK runtime, signature, alias, dependency feature or version change.
Client/server remain immutable public a6. This follow-up publishes no new package.

## Alternatives considered

Recommending a6 before publication would be inaccurate. Relabeling a4/a5 results
would erase verification boundaries. New compatibility helpers, release retries
or another package version provide no benefit for current guidance.

bytes. Fresh-install non-all a6, then check public exports, all 28 help imports,
390 installed files/2358 docstrings, 12 Provider help signatures and three explicit

their exact owned resources absent. Record the separate actual 14-example public-a6

required exact-head CI, including actual public-a6 Docker fixture jobs.

CI and independent review pass before normal merge; old receipts and immutable
